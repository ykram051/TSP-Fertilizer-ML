\chapter{Evidence and Deployment Scope}
\section{Notebook and implementation evidence}
The report is based on the repository notebooks \texttt{01} through \texttt{08}, their generated CSV artifacts, the existing technical reports, and the deployment source code. The following progression was retained: exploratory analysis, prepared feature sets, direct benchmark, delta and transition analysis, target-free virtual sensing, robust candidate comparison, global and local hybrid research and JITL research. The source artifacts remain the detailed audit record for all rows, folds, coefficients, predictions and configuration values summarized here.

\section{Terms that require supervisor confirmation}
Before production shadow mode, the following repository items require owner validation: exact engineering units and material basis for several flow and thermal signals; recycle stream meaning; correspondence between slurry mass and combined volumetric streams; actual event labels; source timestamp and freshness policy for laboratory free acid; DCS vendor and endpoint; Node IDs; OPC UA certificates and security policy; network route; retention and access policy; and the decision cost of errors and warnings.

\section{Software verification scope}
The deployment repository includes unit tests for storage, quality checks, buffer chronology, configuration, resilience and dashboard data access. These checks exercise software behavior. They do not validate the chemical process, sensor calibration, industrial cybersecurity, plant availability, or the business usefulness of an advisory prediction.
