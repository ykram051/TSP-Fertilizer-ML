\section{Resilience, monitoring dashboard and delivery}\label{sec:dashboard}
The service refreshes its health file every five seconds, including when no new row arrives. An OPC sequence watchdog polls the sequence node during quiet periods to reveal a broken subscription or a gateway reset; connection closure or a sequence reset clears incompatible history, sets \texttt{DISCONNECTED} and starts bounded reconnection attempts. After recovery a new \texttt{run\_id} is created, the buffer warms up again, and old-run predictions are never shown as current. The simulator waits for an acknowledgement after each sequence so that fast replay cannot skip rows; this flow control is laboratory-only and must be disabled with a real plant source. The monitoring surface is a native desktop application (PySide6 with a PyQtGraph timeline). It never blocks on I/O: a one-shot reader task runs on the Qt thread pool every two seconds, at most one at a time, and re-reads the trend history every fifth poll (about ten seconds). The SQLite file is opened with a \texttt{mode=ro} URI, \texttt{PRAGMA query\_only} and a 500~ms busy timeout, and connections are closed deterministically to avoid Windows file-locking problems. The dashboard offers status and quality cards, a prediction timeline with selectable range, imputed-input markers, the change since the previous prediction, and a heartbeat watchdog whose threshold (30, 90 or 180 s, or off) separates a quiet process from a stale service.

The timeline is interactive: hovering finds the nearest sample by binary search on the ascending timestamp array and draws a crosshair and an inspector with the exact time, value and whether the inputs were measured or imputed, and a click pins that point. The dashboard reads runtime output only and has no path to the plant.

For delivery on a Windows workstation, the dashboard is frozen with PyInstaller (\texttt{--onefile --noconsole}), a launcher script starts Docker Desktop if needed and brings up the services without rebuilding (loading an offline image archive when present), and a packaging script produces a single ZIP release. Six unit-test modules cover the rolling buffer, configuration, quality shield, storage, service resilience and dashboard data access. These tests exercise software behaviour only; they do not validate the chemistry, sensor calibration, industrial cybersecurity or the business usefulness of a prediction.
